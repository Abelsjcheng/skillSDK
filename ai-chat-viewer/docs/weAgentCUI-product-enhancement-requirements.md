# WeAgentCUI 产品增强需求

## 1. 背景

`weAgentCUI` 是一个面向 Agent 的对话界面，当前已具备流式回答、思考内容、工具调用、权限确认、子 Agent、结构化追问及会话历史等能力。对比豆包、DeepSeek、元宝等成熟 AI 对话产品，当前的主要差距不在基础消息渲染，而在于将已有 Agent 协议能力转化为完整、可发现的用户流程，以及补齐高频输入、结果复用和任务可控体验。

本文档定义 `weAgentCUI` 的产品增强需求，供产品评审、协议评估和研发排期使用。

## 2. 目标

1. 支持文本以外的常见企业对话输入，重点覆盖附件和图片。
2. 让用户在 Agent 执行过程中清楚了解进度、错误和可恢复操作。
3. 通过回答操作和业务导出，使完成的结果可复用。
4. 让长会话和大量历史会话具备可检索、可管理能力。
5. 保持移动端与 PC 小程序功能一致，并针对不同设备提供合适的控件形态。

## 3. 非目标

1. 本阶段不重构助理创建、助理选择和助理详情页面。
2. 本阶段不展示原始思维链。思考区仅允许展示执行摘要或后端明确允许的推理内容。
3. 本阶段不要求接入新的模型供应商，模型路由保留为后端可选能力。
4. 本文档不规定最终视觉设计 Token，具体实现须遵循现有主题和暗黑模式规范。

## 4. 现有能力基线

| 领域 | 已有能力 | 当前限制 |
| --- | --- | --- |
| 消息渲染 | Markdown、代码、公式、流式文本、文件、错误信息 | `weAgentCUI` 未开启回答操作区 |
| Agent 执行 | 思考、工具调用、权限、追问、子 Agent | 信息分散在多个卡片中，缺少任务级摘要 |
| 会话 | 新建会话、历史侧栏、按日期分组、分页 | 不支持搜索、重命名、删除、置顶和结果预览 |
| 输入 | 文本输入、停止生成、PC 发送快捷键设置 | 仅支持文本，且显式禁用了拖放 |
| 现有集成钩子 | 聊天层已有复制、发送至 IM 回调 | `weAgentCUI` 未向用户开放 |

## 5. 与业界竞品的能力差距

下表区分 `weAgentCUI` 当前未具备的功能和已有但体验不足的功能，并归纳豆包、DeepSeek、元宝等主流 AI 对话产品的常见实现。

| 类别 | WeAgentCUI 当前情况 | 业界竞品常见能力 | 优化方向 |
| --- | --- | --- | --- |
| 多模态输入 | **未具备**。输入框仅支持文本，PC/移动端均阻止拖放文件。 | 豆包、元宝普遍支持图片、文件、相机、粘贴图片；DeepSeek 的文件/图片能力随版本和模型开放。 | 图片、文件、相机、粘贴、拖放；提供上传预览、进度、失败重试。 |
| 回答操作 | **底层已有，页面未开放**。已有复制、发送 IM 回调，但 `weAgentCUI` 未启用消息操作栏。 | 复制、重新生成、继续生成、编辑后重发、好评/差评、分享是主流标配。 | 优先开放复制、重新生成、编辑重发、反馈、发送 IM。 |
| 联网搜索与引用 | **未明确具备**。暂无专门的引用来源渲染能力。 | 搜索回答通常包含来源列表、文中编号引用、网页摘要和跳转入口。 | 增加来源卡、文中引用、更新时间、权限/失效状态和“仅基于资料回答”。 |
| Agent 过程展示 | **已有但体验不足**。已有思考、工具、子任务、权限卡，信息分散，用户需自行理解任务进度。 | 通常以“正在搜索/分析/生成”等简洁状态反馈为主；复杂任务提供步骤汇总。 | 增加回答级执行摘要：当前步骤、完成数、耗时、失败原因；细节默认折叠。 |
| 思考内容 | **已有但可读性不足**。直接渲染思考内容，可能过长并挤占正文。 | 常展示“已深度思考 xx 秒”或可折叠的推理过程，默认优先展示结论。 | 改为“执行摘要 + 耗时 + 展开详情”，避免暴露冗长原始推理。 |
| 工具调用 | **已有但偏技术化**。工具卡展示 `Input/Output` 和 `Pending/Running` 等技术或英文状态。 | 面向用户的产品转译为“正在检索资料”“正在读取文档”，原始参数仅在详情中查看。 | 状态中文化；展示业务名称、结果摘要、耗时、重试；原始输入输出二级折叠。 |
| 错误恢复 | **已有错误块，但恢复动作不足**。 | 通常提供重新生成、重试、检查网络、修改问题等明确出口。 | 区分网络、权限、工具、内容错误，并提供“重试本步骤/重新生成/修改后重试”。 |
| 子 Agent | **已有但不够聚合**。子任务嵌套后层级深，最终贡献不突出。 | 复杂任务优先展示任务目标、状态和阶段结论。 | 默认展示“目标、进度、耗时、一句话结论”，详细过程按需展开。 |
| 权限和追问 | **已有**。已支持权限确认和结构化问题。 | 通常解释“为何需要此权限”“确认后会做什么”。 | 增加权限用途、影响范围、拒绝后的替代方案；操作完成后保留结果记录。 |
| 流式阅读 | **已有基础能力但不完整**。用户离开底部后可停止自动滚动，但没有“回到最新消息”入口和未读提示。 | 连续输出场景普遍提供新内容提示和回到底部操作。 | 增加悬浮“回到最新消息”、未读计数和生成中稳定定位。 |
| 会话历史 | **已有基础能力**。支持按日期分组、分页和切换会话。 | 通常支持搜索、重命名、删除、置顶和标题预览。 | 增加会话搜索、重命名、删除、置顶、最后消息/结论预览。 |
| 长回答阅读 | **已有 Markdown，但缺少导航与摘要**。 | 通常通过标题层级、引用、结论卡片、表格和代码优化降低阅读负担。 | 结论先行、自动摘要、目录锚点、长内容折叠、表格横滑、代码语言和文件信息。 |
| 文件结果展示 | **已有基础文件分片**。主要展示文件名和链接。 | 通常展示缩略图、文件类型、大小、页数、预览和下载。 | 按文件类型提供专用卡片；支持图片预览、文档摘要、下载和权限说明。 |
| 对话模式 | **未具备**。 | 常见联网、深度思考、图片/文档分析等模式；DeepSeek 强调深度思考与联网搜索。 | 提供快速回答、深度分析、联网/知识搜索、文档分析、执行任务，由助理能力动态决定。 |
| 结果复用 | **较弱**。回答主要停留在聊天消息中。 | 通常支持分享、导出、转文档、转待办、发送 IM 等。 | 将摘要、表格、待办、代码识别为可保存、可转发的业务产物。 |
| 语音与实时能力 | **未具备**。 | 移动端常见语音输入、语音播报和实时转写。 | 后续接入语音输入、TTS、会议纪要和实时问答。 |

最明显的缺口为：附件输入、回答操作栏、引用来源、会话管理和对话模式。已有能力中最需优化的是：思考块、工具卡、子任务卡、错误块和流式滚动。整体应从“技术事件展示”转为“用户可理解、可干预的任务过程展示”。

## 6. 范围与优先级

| 编号 | 优先级 | 功能 | 简要需求 | 核心验收点 |
| --- | --- | --- | --- | --- |
| REQ-P0-01 | P0 | 多模态输入 | 支持文本、图片和文件；移动端提供相册/文件/相机入口，PC 支持选择、粘贴和拖放；展示上传、重试、移除状态。 | 支持文本、图片、文件及组合消息发送；上传失败可重试；历史会话可正确回显附件。 |
| REQ-P0-02 | P0 | 回答操作栏 | 完成回答提供复制、重新生成、继续生成、编辑重发、好评/差评；宿主支持时可发送至 IM。 | 不影响流式生成；重新生成保留原回答；操作结果有反馈与埋点。 |
| REQ-P0-03 | P0 | Agent 执行时间线 | 汇总思考、工具、权限、追问、子 Agent 的执行步骤，展示状态、耗时、摘要及可重试操作。 | 用户可快速判断当前步骤；失败项可重试；等待用户操作状态明确。 |
| REQ-P0-04 | P0 | 流式对话导航 | 用户浏览历史消息时停止自动滚动；出现“回到最新消息”和未读提示；加载早期消息保持锚点。 | 流式内容不打断历史阅读；可一步回到最新内容。 |
| REQ-P1-01 | P1 | 引用来源与知识范围 | 对网页、知识库和附件生成的结论展示来源、摘要、可访问链接及检索范围；支持仅依据指定资料回答。 | 引用可验证且权限受控；不可访问来源有明确状态。 |
| REQ-P1-02 | P1 | 结果导出与业务流转 | 将回答复制、发送至 IM、保存笔记、创建待办/任务；宿主支持时导出文档。 | 导出成功有明确结果；失败可判断重试、申请权限或更换目标。 |
| REQ-P1-03 | P1 | 增强会话管理 | 支持按标题/内容搜索、重命名、删除、置顶；会话项展示标题、更新时间和预览。 | 可定位历史会话；重命名即时生效；删除后不可再选择。 |
| REQ-P1-04 | P1 | 对话模式与能力说明 | 提供快速回答、深度分析、联网/知识搜索、文档分析、执行任务等模式；由助理能力动态决定可见项。 | 不同助理展示对应模式；所选模式随请求和历史消息保存。 |
| REQ-P2-01 | P2 | 语音与实时交互 | 支持语音输入、回答朗读、实时转写及会议问答/总结。 | 依赖宿主音频能力，后续评估。 |
| REQ-P2-02 | P2 | 协作与审批流 | 支持分享会话、@同事、转审批/任务、订阅任务完成通知。 | 依赖协作及流程平台能力，后续评估。 |

## 7. 协议与 SDK 依赖

| 能力 | 所需协议扩展 |
| --- | --- |
| 附件输入 | 上传生命周期、文件元数据、消息附件载荷、下载/预览授权 |
| 重新生成/继续生成/编辑重发 | 回答版本标识、重新生成和继续生成操作、请求链路标识 |
| 反馈 | 消息级评分及可选原因提交 |
| 执行时间线 | 稳定步骤 ID、父任务 ID、状态、耗时、是否可重试、简明摘要 |
| 来源引用 | 引用 ID、来源类型、标题、受许可定位信息、摘要、可用状态 |
| 结果导出 | 目标能力发现、操作请求、成功标识或 URL、错误码 |
| 会话管理 | 搜索、重命名、删除、置顶 API 及缓存失效语义 |
| 对话模式 | 助理能力声明及发送消息请求中的模式字段 |

## 8. 现有实现复用

1. `MessageBubble` 已支持思考、工具、追问、权限、文件、错误和子任务消息分片渲染。
2. `useChatSession` 已管理流式消息、停止生成、历史分页、追问提交、复制和发送至 IM 回调。
3. `Content` 已在加载早期历史消息时保持滚动锚点。
4. `WeAgentHistorySidebar` 已具备按日期分组、分页和会话选择能力。
5. `WeAgentCUIFooter` 已提供 PC 工具栏插槽（`leftActions`），可用于接入附件和模式控件。

实现应优先开放和扩展上述路径，不应建立一套平行的聊天架构。

## 9. 数据度量

按平台、助理和能力模式（适用时）记录以下事件和结果指标：

1. 附件选择、上传成功/失败/重试、附件发送完成。
2. 回答操作曝光和使用：复制、重新生成、继续生成、编辑重发、反馈、IM 发送。
3. Agent 时间线展开率、工具重试率、权限完成率、任务完成率。
4. 流式生成中的“回到最新消息”使用率、历史消息加载失败率。
5. 搜索成功率、会话重命名/删除/置顶使用率、历史会话选择率。
6. 引用打开率、来源不可用率、导出成功/失败率。
7. 首次响应耗时中位数、端到端任务时长、停止生成率、用户差评率。

## 10. 交付建议

建议按以下顺序交付：

1. P0：输入、回答操作、执行时间线和流式导航。
2. P1：引用来源、结果导出、会话管理和任务模式。
3. P2：待宿主和后端能力确认后，再推进语音和协作工作流。

首个版本建议作为完整的“输入与执行可控性”版本交付。它可为现有的所有 Agent 对话提供直接可见价值，并显著提升当前工具、权限、子 Agent 和流式能力的可用性。
